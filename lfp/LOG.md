## 2026-09-21 — v4.1 (three layers of rules, raised questions, staleness, observed reality, agents from spec)
- **Three loops, not one big invariant list** (decision, after a literature review): **meta** (kernel constraints → `checks.ts::checkInvariants` → *raised questions*, never auto-repaired), **representation → reality** (a rule's condition → a test naming it → a task, closed by a Builder agent then a Reviewer), **clarification** (an agent that can't derive a measurable "done" raises a question and blocks its task until the user answers). `docs/AGENT-RUNTIME.md` (hand-written, not generated) records how these map onto Flue.
- **Data model split out of `store.ts`** (Stage 0): new Node-runnable `src/types.ts` (`Node`, `Edge`, `Graph`, `AICall`, `Effect`, `Violation`, `OpenItem`, …) and `src/checks.ts` (`checkInvariants(graph)`, pure, imports only `kernel.ts`/`types.ts` — so `scripts/*.mjs` can run it without pulling in the browser store). `Node` gained `v`/`hash`; `Edge` gained `trace: 'valid' | 'suspect'`.
- **Edits are effects too, with staleness** (S145+): `store.ts::commit`/`directCommit` bump a node's `v` and mark every edge touching it `suspect` whenever its title/description/props actually change (djb2 `contentHash`); `revalidate(nodeId)` recomputes the hash — unchanged clears the node's edges back to `valid` (the early cutoff: the spread stops there), changed bumps `v` again and cascades. The Talk panel surfaces this as a suspect strip (`talk-suspect`, `talk-revalidate`) whenever `ctx.suspect.edges > 0`.
- **Raised questions replace silent violations**: `syncRaised()` turns every `checkInvariants` result with `raise: 'question'` into a `FollowUp` (`raisedBy: { kind: 'violation' | 'agent' | 'contradiction' | 'template', ref }`), created/removed on every hydrate/commit/undo/revalidate; `rankOpen()` ranks everything open into four tiers — blocking agent questions, the next template question, violation-raised threads (by space order), then the rest — and is what `Context.next` and the Talk panel's "Now" strip show (`talk-next`, `talk-next-tier` badge). The seed graph carries **34 active violations** (15 needs-cardinality, 9 rule-condition-has-test, 5 test-has-rule, 3 test-without-passing-fresh-result-and-no-task, 2 protocol-realised) — all surfaced, none silently fixed. `Definition.vue` shows raised follow-ups inline under their parent question with a source badge (`def-raised`).
- **Outcomes close the efficacy loop** (S128–S131 extended): every `AICall` can now carry `outcome: { state: 'approved' | 'edited' | 'discarded' | 'ignored', editDistance? }` — recorded by the Talk panel when the user approves (with a Levenshtein-based edit distance if they double-click-edited a staged line first), discards, or lets a new changeset replace an unanswered one (`ignored`). Reference's efficacy table (`ref-ai-efficacy`) adds approved/edited/discarded/ignored percentages and median edit distance per function/version, flagged "provisional" under 30 calls.
- **Observed reality, not asserted reality**: `src/reality.json` (new, gitignored contents merged in, structure `{ results, metrics }`) holds test-result statuses and metrics observed by running things, not hand-entered; `store.ts::hydrate()` patches them onto the `test-result` nodes that `reports` each test. `scripts/observe.mjs` runs `smoke.mjs` with `REALITY_OUT` set (each check now wrapped in `t('test-<id>', fn)` when a matching `test` node exists in the graph), merges pass/fail per test id plus git/violation metrics into `reality.json`. `scripts/dispatch.mjs <taskId>` prints a work order (rule lines + tests + conditions + an acceptance line: full suite green + reviewer verdict) to stdout and `scratch/workorders/<task>.md`, and `dispatch <taskId> --state <s>` walks the task's `queued → running → blocked ↔ running → done → verified` lifecycle in `graph.json`.
- **Agents declared from one spec, not scattered code** (Stage 1-F, in progress alongside Stage 3): `src/agents.ts` holds `AGENTS: AgentSpec[]` (talk, observer, planner, builder, reviewer, clarifier) with `tier`, `hosting: 'top' | 'delegate' | 'path'`, `tools`, `aiFunctions`, `sandbox`, `budget`, one `TIER_MODELS` map (OpenRouter, one key, every vendor as `openrouter/<vendor>/<model>`) — `kernelDigest()` now lists every agent, and `docs/AGENT-RUNTIME.md`'s `hosting` field was corrected on review to match the shipped type. `agent/agents/from-spec.ts` turns a spec into Flue hooks (`useModel`/`useTool`/`useSandbox`/`useSubagent`) so the spec stays the single source of truth for model, tools, budget and checkpoint; sqlite persistence backs the agent runtime's durability.
